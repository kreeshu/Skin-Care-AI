System Map

The project combines one learned vision component with deterministic rules, catalog ranking, and an optional language model.

1

Input

Facial image, optional user-stated skin type, and an optional request for SLM explanations.

↓
2

API validation

FastAPI checks image MIME type and a 10 MiB size limit; Pillow decodes the image.

↓
3

Image preparation

Convert to RGB, reject dimensions below 64 pixels, resize to 224 × 224, and add a batch dimension.

↓
4

Vision inference

EfficientNetB0 produces five independent scores: blemishes, dark spots, redness, visible pores, and fine lines.

↓
5

Decision thresholds

Each score becomes present, absent, or uncertain using its own threshold and a ±0.05 uncertainty margin.

↓
6

Deterministic recommendation

Only present concerns become ingredient and product-category requirements. Catalog products are scored and ranked.

↓ optional
7

Grounded SLM

Qwen may rerank the approved shortlist and explain an AM/PM routine. Invented product IDs are removed.

↓
8

Output

Concern states, stated skin type, ranked products, routine, disclaimer, and optional generated explanations.

Boundary to remember

The system reports visible cosmetic concerns. It does not diagnose disease, infer skin type from a photograph, or prove that a recommended product will work.

Truth table

Learned

Vision model

Learns visual patterns from labeled images and produces concern scores.

Programmed

Rule engine

Maps present concerns to ingredients and categories written by the developers.

Programmed

Product ranker

Combines ingredient match, rating, reviews, availability, discount, and optional skin-type match.

Generative

Qwen SLM

Produces language from constrained candidate facts; it is not the vision classifier.
